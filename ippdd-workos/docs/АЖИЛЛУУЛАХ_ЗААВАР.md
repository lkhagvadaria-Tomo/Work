# IPPDD WorkOS — Шууд ажиллуулах заавар

Код бүрэн бэлэн. Ажиллуулахад **таны эрхээр хийгдэх ёстой 3 гадаад тохиргоо** л үлдсэн:
Supabase project, Google OAuth client, хостинг. Нийт ~30–40 минут.

---

## Хувилбар А — Локал демо (5 минут, ямар ч бүртгэлгүйгээр)

Багт үзүүлэх, туршихад. PostgreSQL суусан компьютер дээр:

```bash
cd ippdd-workos
npm install
npm run setup      # өгөгдлийн сан + пилот OKR + .env.local автоматаар
npm run dev        # → http://localhost:3000
```

Нэвтрэх: login хуудасны **persona сонголтоор** (Лхагвадарь / Онон / Мөнх-Эрдэнэ / Admin).
Бүтэн урсгалыг үзэх demo: `su postgres -c "psql -d workos -f $PWD/scripts/dev/close-quarter-demo.sql"`
— бүх ажил → KR → улирлыг жинхэнэ гейт+sign-off замаар хааж, гэрчилгээ гаргана.

## Хувилбар Б — Production идэвхжүүлэлт

### 1-р алхам · Supabase project (~10 мин)

1. https://supabase.com → **New project** (нэр: `ippdd-workos`, регион: Singapore ойр).
2. Project үүсмэгц: **Settings → Database → Connection string → URI** (direct, 5432)
   утгыг хуулж авна.
3. Энэ репогоос нэг команд ажиллуулна:

```bash
DATABASE_URL='postgresql://postgres:НУУЦ_ҮГ@db.XXXX.supabase.co:5432/postgres' \
  npm run deploy:db
```

Скрипт миграц + тохиргоо + пилот OKR-ийг суулгаад баталгаажуулна
(3 ажилтан, 3 зорилт, 10 KR, 5 ажил). Dev persona **орохгүй** — ажилтнууд зөвхөн
Google-ээр нэвтэрнэ. Давхар суулгахаас өөрөө сэргийлнэ.

### 2-р алхам · Google OAuth (~10 мин, Workspace админ эрхээр)

1. https://console.cloud.google.com → APIs & Services → **Credentials → Create
   OAuth client ID** (Web application).
2. **Authorized redirect URI:** `https://XXXX.supabase.co/auth/v1/callback`
   (Supabase → Authentication → Providers → Google дээр яг энэ URI бичээстэй байгаа).
3. OAuth consent screen-ийг **Internal** болговол зөвхөн netgroup.mn данс нэвтэрнэ.
4. Client ID/Secret-ийг Supabase → **Authentication → Providers → Google** дээр
   буулгаж идэвхжүүлнэ.

### 3-р алхам · Хостинг (Vercel, ~10 мин)

1. https://vercel.com → **Import** энэ GitHub репо → Root Directory: `ippdd-workos`.
2. Environment Variables (бүгд `.env.example`-д тайлбартай):

| Хувьсагч | Утга |
|---|---|
| `NEXT_PUBLIC_APP_URL` | Vercel-ээс өгсөн домэйн, ж: `https://ippdd-workos.vercel.app` |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | мөн тэндээс (publishable/anon) |
| `SUPABASE_SECRET_KEY` | мөн тэндээс (secret) — **зөвхөн сервер** |
| `DATABASE_URL` | Connection string (**Transaction pooler, 6543 порт**) |
| `SESSION_SECRET` | урт санамсаргүй тэмдэгт мөр |
| `GOOGLE_WORKSPACE_DOMAIN` | `netgroup.mn` |
| `AI_PROVIDER` | `mock` (гадаад AI-г аюулгүй байдлын шийдвэрийн дараа асаана) |

   ⚠ `DEV_AUTH` — production-д ХЭЗЭЭ Ч тавихгүй (тавьсан ч build-д хаалттай).
3. **Deploy** дарна.
4. Supabase → Authentication → **URL Configuration**: Site URL = танай домэйн,
   Redirect URLs-д `https://<домэйн>/auth/callback` нэмнэ.

### 4-р алхам · Баталгаажуулалт (~5 мин)

- [ ] `https://<домэйн>/login` — «Google-ээр нэвтрэх» товч харагдана
- [ ] Мөнх-Эрдэнэ, Лхагвадарь, Онон нэвтрэхэд dashboard нээгдэнэ (анхны нэвтрэлтээр
      эрх автоматаар холбогдоно — админ урьдчилан бүртгэсэн 3 и-мэйл л орно)
- [ ] Өөр Google данс → «Хандах эрхгүй» хуудас
- [ ] Лхагвадарь: Миний OKR-д 3 зорилт, 10 KR харагдана
- [ ] Ажил дээр CLOSED-ийг гараар тавих ямар ч товч байхгүй — зөвхөн
      SUBMIT FOR CLOSURE → гейт → захирлын sign-off

### Дараа нь (шаардлагатай үед)

- **Шинэ ажилтан:** нэвтэрсэн админ → Админ → Ажилтнууд → нэмэх (Workspace и-мэйлээр).
  Анхны админ эрх: Supabase SQL editor-т
  `update employees set system_role='ADMIN' where email='munkh-erdene.o@netgroup.mn';`
- **Q4 улирал:** Админ → Улирлууд → Шинэ улирал; OKR-ийг `scripts/import-okr.ts`-ээр
  импортлоно (README-д заавартай).
- **Drive metadata (батлагдсаны дараах өөрчлөлт илрүүлэх):** Supabase Google provider-ийн
  scopes-д `https://www.googleapis.com/auth/drive.metadata.readonly` нэмнэ
  (docs/GOOGLE_DRIVE.md).
- **AI-г асаах:** `AI_PROVIDER=anthropic`, `AI_API_KEY`, `AI_MODEL` — өгөгдлийн урсгалын
  тайлбар docs/SECURITY_CHECKLIST.md-д. AI зөвхөн зөвлөнө; батлах эрх хэзээ ч үгүй.

## Асуудал гарвал

| Шинж тэмдэг | Шалтгаан / засвар |
|---|---|
| Нэвтэрсэн ч «Хандах эрхгүй» | Тухайн и-мэйл employees-д бүртгэлгүй/идэвхгүй — админ бүртгэнэ |
| Google товч дархад алдаа | Redirect URI Supabase callback-тай таарахгүй — 2-р алхмыг шалга |
| Хуудас хоосон, серверийн алдаа | `DATABASE_URL` буруу (pooler 6543 эсэхийг шалга) |
| deploy:db «схем аль хэдийн байна» | Санаатай хамгаалалт — цэвэр project дээр ажиллуул |

Дэлгэрэнгүй: docs/DEPLOYMENT.md (англи, илүү техник), docs/OPERATIONS.md (өдөр тутмын
ажиллагаа), docs/SECURITY_CHECKLIST.md.
